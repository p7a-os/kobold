# Kobold Thin Harness Tasks

## Status Overview

- **Architecture Plan**: Modular Rust monorepo under `crates/`.
- **Target Design**: Thin agent harness decoupling frontends, daemon, kernel, tools, and model backends.
- **Current Phase**: Implementation (TASK-3 ready, TASK-1 & TASK-2 completed).

---

## Tasks

### TASK-1: Workspace Skeleton & `kobold-types` Crate
- **Status**: Completed
- **Scope**:
  - Configure root `Cargo.toml` with workspace members under `crates/*`.
  - Create `crates/kobold-types` crate with zero operational logic and minimal dependencies (`serde`).
  - Define data models in `kobold-types`: `Message`, `Role`, `ToolDefinition`, `ToolCall`, `ToolOutput`, `KernelEvent`.
  - Define trait contracts in `kobold-types`: `Backend` (model inference/streaming), `Tool` (metadata & execution), `EventSink` (event observation), and `ApprovalPolicy` (permission check).
- **Acceptance Criteria**:
  - `cargo check --workspace` compiles cleanly.
  - `crates/kobold-types` has zero network, process, or filesystem I/O dependencies.

### TASK-2: `kobold-context` Conversation & Compaction Crate
- **Status**: Completed
- **Scope**:
  - Create `crates/kobold-context` crate depending on `kobold-types`.
  - Implement conversation message history tracking and deterministic ordering.
  - Implement hybrid token budgeting (reconciling exact provider `Usage` counts with fast ~4 chars/token buffer heuristics).
  - Implement two-tier context compaction:
    1. Prune historical tool outputs to concise provenance reference markers.
    2. Slide intermediate turns when exceeding budget, strictly preserving the system prompt and initial user task.
  - Implement system prompt construction, automatically discovering and injecting `AGENTS.md` (strictly ignoring `CLAUDE.md`).
- **Acceptance Criteria**:
  - Isolated unit tests verifying message history appending, hybrid token reconciliation, tool output pruning, and sliding window.
  - Verification that `AGENTS.md` is discovered and injected into the system prompt while `CLAUDE.md` is ignored.
  - Zero network, process, or filesystem I/O dependencies.

### TASK-3: `kobold-kernel` Agentic Loop & Turn Orchestrator

### TASK-4: Execution Tools (`kobold-tool-bash`, `kobold-tool-fs`)
- **Status**: Completed (2026-09-09)
- **Scope**:
  - **Unified Execution Targets (`D-35`, `D-36`)**:
    - Dual sandbox mode: `MicroVm` sandbox (default on Apple Silicon) and `HostProcess` sandbox (`--sandbox host` for native macOS/Xcode toolchains).
    - In `MicroVm` mode, both `kobold-tool-bash` and `kobold-tool-fs` operate on the guest filesystem via vsock, eliminating filesystem split-brain and keeping host working tree pristine until `git bundle` export.
  - **`crates/kobold-tool-bash`**:
    - Implement `Tool` trait for a unified `bash` tool (one-shot by default, persistent with `session_id`).
    - macOS `Virtualization.framework` microVM driver with APFS CoW checkpoints (`clonefile`).
    - Lazy microVM boot: boots on first tool execution, skipping startup overhead for read-only turns (`D-37`).
    - Static Rust PID-1 agent in `initramfs` communicating over vsock using length-prefixed JSON.
    - Quiesced snapshot protocol (`FIFREEZE` / `F_FULLFSYNC` / `clonefile` / `FITHAW`).
    - Git repository sync via `git bundle` (host import and branch export).
    - Timeouts and output truncation.
  - **`crates/kobold-tool-fs`**:
    - Implement `Tool` trait for structured operations: `read_file`, `write_file`, `edit_file`, and `list_dir`.
    - Dispatches through the vsock guest agent in `MicroVm` mode, or in-process in `HostProcess` mode.
- **Acceptance Criteria**:
  - `kobold-tool-bash` and `kobold-tool-fs` operate coherently on the exact same filesystem (changes from `write_file` are immediately visible to `bash("cargo check")`).
  - Checkpoint creation and rewind verified on APFS with sub-second commit latency.
  - Codebase changes exported via `git bundle` to dedicated host branch without modifying host working tree.
  - Opt-in `--sandbox host` executes directly against host with security warnings.
- **Verification**: Verified via `.agent-reports/2026-09-09-task-4-execution-tools/verify.sh` (11 unit tests passing, clean clippy, 36 workspace tests passing).

### TASK-5: OpenAI Backend (`kobold-backend-openai`)
- **Status**: Completed (2026-09-09)
- **Scope**:

  - Implement bidirectional streaming client using the OpenAI Realtime / Responses WebSocket protocol.

- **Acceptance Criteria**:

### TASK-6: In-Process SDK & Session Runtime (`kobold-runtime`)
- **Status**: Completed
- **Scope**:
  - Create `crates/kobold-runtime` as the primary in-process Rust SDK crate.
  - Implement `AgentSession` / `SessionBuilder` API:
    - Binds workspace directory and automatically builds `ConversationHistory` with `AGENTS.md` and environment metadata.
    - Registers tools (`kobold-tool-bash`, `kobold-tool-fs`) and backend (`kobold-backend-openai`).
    - Configures approval policies and attaches transcript DAG persistence (`.kobold/transcript.jsonl`).
    - Exposes high-level async prompt execution: `session.prompt(text) -> Result<TurnResult, RuntimeError>`.
  - Zero socket listeners, zero IPC overhead: directly embeddable into any Rust binary or CLI tool.
- **Acceptance Criteria**:
  - Unit and integration tests running multi-turn agent sessions entirely in-process.
  - Verified transcript DAG persistence across turns.
- **Verification**: Verified via `.agent-reports/2026-09-09-task-6-kobold-runtime/verify.sh` (8 unit/integration tests passing including live OpenAI streaming, zero clippy warnings, 49 tests passing across all thin harness crates).

### TASK-7: Daemon & Frontends (`kobold-server`, `kobold-client-cli`, `kobold-client-tui`)
- **Status**: Ready for Implementation
- **Scope**:
  - **`crates/kobold-server` (`D-33`, `D-37`)**:
    - Supervisory daemon managing multi-session routing across workspaces.
    - Spawns isolated worker child processes per session running `kobold-runtime`, eliminating crash blast radius and memory leaks.
    - Evicts detached idle worker processes after 30 minutes of inactivity.
    - Dual IPC transport: Unix Domain Socket listener and WebSocket listener.
    - Enforces single-writer `UI Lease` (`D-38`) across concurrent client attachments.
  - **`crates/kobold-client-cli`**:
    - Fast terminal client connecting to `kobold-server` via UDS (or running embedded via `kobold-runtime`), with `/zdr` command and status display.
  - **`crates/kobold-client-tui` (`D-38`)**:
    - Interactive Terminal UI built on Ratatui conforming to 3-pane layout specification:
      - Header Line: `Kobold v0.1.0` | `workspace` | `branch` | `[ZDR]` indicator.
      - Transcript Pane: Markdown stream with `AGENTS.md` rules badge.
      - Input Bar: Single-writer prompt input and diff-based approval dialogues.
- **Acceptance Criteria**:
  - Multi-session daemon routes UDS and WS traffic to correct isolated worker subprocesses.
  - Worker process crash does not affect daemon or neighboring sessions.
  - TUI 3-pane layout renders status, rules badge, and diff approvals cleanly.
  - Toggling `/zdr on|off` updates runtime retention and reflects `[ZDR]` indicator in the status line.
