# Command-Line Interface & Daemons

Kobold provides flexible execution modes for local terminal use, background daemons, and one-shot scripting.

---

## 1. Interactive Client (`kobold`)

```sh
# Start an interactive TUI session in the current directory
kobold

# Start with a specific adapter
kobold --adapter ./target/release/kobold-adapter-acp

# Attach to an existing daemon session
kobold attach <session_id>

# Run in debug mode (prints raw tool and protocol traffic in transcript)
kobold --debug
```

---

## 2. Headless Daemon Supervisor (`koboldd`)

```sh
koboldd \
  --socket /tmp/kobold-501/my-session.sock \
  --session my-session \
  --workdir /path/to/repo \
  --adapter ./target/release/kobold-adapter-acp \
  --ws-port 3000
```

### Flags Reference

| Flag | Argument | Description |
| :--- | :--- | :--- |
| `--socket` | `<path>` | Custom path for the Unix Domain Socket. |
| `--session` | `<id>` | Session identifier (defaults to autogenerated UUIDv7). |
| `--workdir` | `<path>` | Target working directory for the agent execution kernel. |
| `--adapter` | `<path>` | Path to the Southbound adapter executable. |
| `--unconfined` | - | Runs adapter without platform sandbox confinement (useful for debugging). |
| `--ws-port` | `<port>` | Port for the optional Northbound WebSocket companion server (default: 3000). |

---

## 3. One-Shot Batch Execution (`-p`)

Execute a single prompt, stream output to stdout, and exit with the model's status code:

```sh
# Pass prompt as an argument
kobold -p "Explain how the Raft consensus algorithm works in 2 paragraphs."

# Pipe prompt from stdin
cat prompt.txt | kobold -p
```
